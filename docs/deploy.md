# Deploying Tapat (free)

Tapat runs on a free Render web service with a free Postgres database on Neon. No card is needed for either. Render's free disk is wiped on every restart, which is why the data goes to Neon instead of a local file.

Time needed: about 15 minutes.

## 1. Create the database on Neon

1. Go to https://neon.tech and click **Sign up**. Sign in with GitHub or Google.
2. Create a project:
   - Project name: `tapat`
   - Postgres version: leave the default
   - Region: **AWS Asia Pacific (Singapore)**, the closest to Manila
   - Click **Create project**.
3. On the project dashboard, click **Connect**.
4. Leave Branch `main`, Database `neondb` and the default role as they are. Turn **Connection pooling** off, so the string has no `-pooler` in the host.
5. Copy the connection string. It looks like:
   `postgresql://neondb_owner:XXXX@ep-something-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
   Keep it somewhere private for step 2. Do not commit it.

Tapat creates its tables on first start, so there is nothing else to do in Neon.

## 2. Create the service on Render with the Blueprint

1. Sign in at https://dashboard.render.com with the existing account.
2. Click **New** (top right), then **Blueprint**.
3. If GitHub isn't connected for this repo yet, click **Configure account** and give Render access to `Troy-LL/tapat`.
4. Next to `Troy-LL/tapat`, click **Connect**.
5. Blueprint name: `tapat`. Branch: `main`. Leave Blueprint Path empty (it uses `render.yaml`).
6. Render lists one new resource, the web service `tapat` on the **Free** plan, and asks for two values:
   - `DATABASE_URL`: paste the Neon connection string from step 1.
   - `ADMIN_PASSWORD`: choose the professor's password. It is stored only in Render, never in the repo. Share it with the professor privately.
   `SECRET_KEY` is generated by Render automatically.
7. Click **Deploy Blueprint**. The first build takes a few minutes.
8. When the service shows **Live**, open it. The address is shown under the service name, for example `https://tapat-xrg5.onrender.com`. Check https://tapat-xrg5.onrender.com/health shows `{"ok":true}`.

Render only asks for `DATABASE_URL` and `ADMIN_PASSWORD` the first time. To change them later, open the service, click **Environment**, edit the value, and click **Save, rebuild, and deploy**.

## 3. Point the extension at the server

The live server is `https://tapat-xrg5.onrender.com`, and the extension already points there (`DEFAULT_SERVER` in `extension/config.js` and `host_permissions` in `extension/manifest.json`).

If the service is ever recreated with a different address:

1. In `extension/config.js`, set `DEFAULT_SERVER` to the new address.
2. In `extension/manifest.json`, replace `https://tapat-xrg5.onrender.com/*` under `host_permissions` with the new address followed by `/*`.
3. Commit, then reload the extension in `chrome://extensions`.

A start link always carries its own server address, so students who paste the full start link reach the right server either way.

## 4. Share the extension with the class

1. Zip the `extension/` folder, or share the repo link.
2. Students open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked**, and pick the `extension/` folder.

## 5. Quiz day

- About a minute before the quiz, open https://tapat-xrg5.onrender.com/admin and log in. The free service sleeps after 15 minutes without traffic, and the first load can take about a minute. That is normal.
- Once students start, the 10-second heartbeats keep the server awake.
- If a student starts while it is still waking, the popup shows "Server waking up…" and waits. Events are queued in the browser and sent once the server answers, so nothing is lost.

## Free tier notes

- Render free web services sleep when idle and have a monthly limit of free instance hours. One class's quizzes fit well inside it.
- Neon's free plan includes a small amount of storage, far more than Tapat's event logs need. Use **Delete logs** after grading.
- No paid add-ons are needed.
